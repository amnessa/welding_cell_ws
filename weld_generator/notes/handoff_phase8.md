## 2. Rulings and conventions that are not written in the code

These were decided in conversation. Do not re-litigate; if one is reopened, note why in
`dataset_plan.md` §10.

- **Ground truth is constructed, never detected** — the one rule. Only exact geometry is
  truth; every choice (D19 seam curve, MPS, tacks, noise realisation) is a versioned rule.
- **`ours` (radius-PCA) is excluded from the comparison** (user, 2026-09-03). The project's
  own contribution is the improvement built on the winner. `--include-ours` exists if a
  floor-anchor figure is ever wanted.
- **The corpus is homogeneous per FAMILY (60 each), not per class.** T = 360, butt = 180,
  corner/lap/edge = 60. Report per stratum, never pooled. Straight lines are family 1.
- **Grooved butts stay in the corpus, the table AND the training split** — the D28 failure
  was a constructor omission (fixed by `PreparedPrism`), and the methods' failure on grooves
  is the groove, not the outline (measured before/after: unchanged).
- **T joints split into T-joint (3.10) and angle joint (3.12)** per ISO 17659 — stratify by
  `iso_17659_term` (in `facts.csv`); it is a reportable row (lit-ppf 0,63 → 0,03).
- **The "tack version" is the same corpus** — rule blocks are applied in place
  (`apply_rule_blocks.py`), identity preserved, hashes rewritten. Never a second corpus.
- **Meshes are emitted only after all phases through 7 are closed** — they are (now):
  `python -m weldgen generate ... --emit-meshes` regenerates them deterministically, or add
  a mesh-export pass to `apply_rule_blocks.py`-style script (meshes are unhashed).
- **`camera_raster` (D20) and `approach_cone` (D26) twin arms of bench_phase4 are on the
  runway** — noted, to be completed "along the way"; both are non-geometry keys (twins).
- **lit-nurbs was dropped** (RANSAC first, planar butt only); **lit-quadric** replaced it.
- **lit-quadric runs with the corrected chain ordering in every standard chunk; the
  as-published distance ordering is the `quadric_distance_*` rung** (the fold made one
  chunk take 8,9 h — scoring cost, not method cost).
- **The config_id lesson**: `config_id` hashes the RESOLVED config, so any new
  `DEFAULT_CONFIG` key re-ids every corpus. New flags are opt-in per config file
  (`emit_mps`, `emit_tacks`, `camera_regime`); new random draws are APPENDED to a
  substream. This will matter in Phase 8 (material/lighting draws → a new substream + an
  opt-in `render` block, never a default key).
- **D39**: any scoring on closed seams must be rotation-invariant; `end_error_mm` is NaN on
  rings.
- **Phase 5**: the annotator's intra-rater repeat (~8 scenes) is still owed by the user; the
  demo pass is excluded from all numbers (different measurement, not a better one).
- **Citations still to verify in hand**: Tomków, Sobota & Krajewski 2020 (tack anchor),
  EN 1011-2 (tack length attribution), AWS D1.1 for lap overlap.

Practical lessons from long runs: use `nohup ... &` + a log + a watcher (never a bare
`sleep`); **never `pkill -f <pattern>` from a shell whose own command line contains the
pattern** (it kills itself); chunks are resumable per file — parallel runners on disjoint
`--only` groups are safe; `--append-missing` / `--retire` repair the dataframe after a
stratum rebuild.

(which route becomes "our" contribution) is still open and is a results discussion to

## 4. Phase 8 — tier-2 rendering: the plan as agreed

Decisions already taken (dataset_plan.md Phase 8; discussion 2026-09-02):

1. **Backend: Isaac Sim / Omniverse Replicator** (Isaac Sim 5.1.0-rc.19 at `/isaac-sim`,
   `omni.replicator.core` 1.12.27). BlenderProc demoted to an optional portability
   backend. D9 (no simulator in the tier-1 core) is untouched — tier 2 is a pluggable
   backend behind the same schema, and the release ships rendered FILES so nobody needs RTX
   to use them; only re-rendering does.
2. **RGB and depth from one render pass**: attach the `rgb` and `distance_to_image_plane`
   annotators to one render product; store `rgb.png` and `depth.png` (16-bit, mm) plus an
   invalid-pixel mask in the scene directory next to `cloud.npz` (the schema already
   reserves both, D10: RGB stored, never benchmarked).
3. **The sensor axis is shared across tiers by construction**: Replicator gives CLEAN
   depth; apply the existing D16 analytic stereo-noise model (`weldgen/noise.py`, the
   named profiles d435i / stereo_good / stereo_poor) to the rendered depth. The
   dot-pattern stereo simulation (render an IR pair, run a block matcher) is the optional
   high-fidelity upgrade, not the plan. Specular dropout and shadow holes: post-processing
   informed by rendered normals/materials.
4. **The camera is PINNED, never randomised**: drive Replicator's camera from the stored
   `camera.T_world_cam` and intrinsics `K`. The tier-2 gate is "differs from the tier-1
   twin only in sensor realism", so Replicator's domain randomisation applies to
   **materials and lighting only** (painted MDF, stainless, mill scale/rust; lighting
   variation) — never geometry or pose.
5. **Config discipline**: material/lighting draws = a NEW append-only substream and an
   opt-in `render:` block in the config file — never a `DEFAULT_CONFIG` key (the config_id
   lesson). `twin_key` must survive; scene ids of existing corpora must not change.
6. **Scene ingestion**: converter `scene.json` + primitives → USD stage. Prefer building
   USD directly from the `weldgen.geom` primitives' `mesh()` (trimesh → `pxr` UsdGeom.Mesh)
   over a PLY round-trip; keep object ids / face ids as primvars so the renderer's
   semantic/instance outputs can be checked against `cloud.npz`.
7. **The validation gate that makes this honest** (build it FIRST, before materials):
   back-project the rendered clean `depth.png` through `K` and `T_world_cam`, and compare
   with the tier-1 `cloud.npz` points visible from that camera — the geometry is identical
   by construction, so the residual is renderer error and must sit inside the D34 chord
   budget (0,25 mm). Also: `visible_from_cam` from tier 1 vs the rendered depth's coverage
   should agree (occlusion is the same ray cast). Make this a test + a notebook cell.
8. **Mechanics**: headless entry `/isaac-sim/python.sh script.py` with
   `SimulationApp({"headless": True})` created BEFORE any `omni.replicator.core` import
   (the module will not import from a plain interpreter). Develop on the 4060 laptop,
   batch on the 5070 Ti (Blackwell — needs a current driver; Isaac 5.1 supports it);
   ~720–1000 scenes at seconds per frame is an evening. A custom Replicator writer emits
   into the existing per-scene directories.
9. **Milestones**: (a) one scene → USD → clean depth → back-projection gate passes;
   (b) writer + schema fields + `weldgen verify` still green (rendered files are unhashed
   like meshes, or hashed — decide and record in SCHEMA.md); (c) D16 noise on rendered
   depth, twin identity test (tier-1 vs tier-2 same seed: identical `scene.json` geometry);
   (d) materials + lighting substream, gate + tests; (e) render `bench_phase4` (+ `_fx`);
   (f) `notebooks/16_tier2.ipynb`: tier-1 vs tier-2 vs (later) real, the ablation the
   shared schema exists for.
10. **Meshes**: emit them now for the corpus (Phase 7 is closed): either add
    `--emit-meshes` to a re-generation, or write a small script that regenerates each
    scene's primitives from `(config, seed)` and exports `mesh_<id>.ply` next to the
    existing files (meshes are unhashed, so ids/hashes are untouched).

Risk named in the plan: "Phase 8 slips — tier 1 must be submission-sufficient on its
own." It is: the paper's tables exist today without tier 2.
